# 바운스 로얄 (Bounce Royale)

4인 PvP 물리 기반 로그라이트 오토배틀러. 원형 캐릭터가 경기장을 직진하며 벽에 반사되고,
회전하는 무기로 싸우는 "서클배틀" 방식의 전투에 매 라운드 증강을 쌓는 빌드 시스템을 결합했다.

## 배포

GitHub Pages로 자동 배포된다. `main` 브랜치에 push하면 1~2분 뒤 반영된다.
설정·주의사항·문제 해결은 [DEPLOY.md](DEPLOY.md) 참고.

## 실행 방법

`index.html`을 더블클릭해 브라우저에서 열면 된다. (별도 설치·서버 불필요)

또는 로컬 서버 사용 시:

```bash
cd bounce-royal
npx serve .        # 또는 python -m http.server
```

## 조작

| 행동 | 조작 |
|---|---|
| 전투 시작 방향 조준 | 내 공 근처에서 **드래그 → 손을 뗀다** (반사 궤도 예측선 표시) |
| 캐릭터 스킬 | 버튼 클릭 또는 키 **1** |
| 무기 전용 스킬 | 버튼 클릭 또는 키 **2** (활 차지 샷은 2회 입력: 충전 → 발사) |
| 공용 스킬(방향 전환) | 전투 중 캔버스 **드래그** 또는 키 **3** 후 드래그 |

모바일 화면은 **720×1280(9:16) 세로 모드**를 기준으로 구성되어 있다. 타이틀에서 경쟁전, 친선전,
가방, 도감, 설정으로 이동하며 가방에서 장착한 캐릭터가 다음 매치에 사용된다.

## 규칙 요약

- 패배 시 코인 -1, 코인 0이면 탈락. 마지막 1인이 우승 (코인 = 목숨 = 전략 자원)
- 전투 30초 → 연장전 10초(1배속에서 시작해 5초에 걸쳐 2배속까지 가속) → 남은 체력 **비율**이 높은 쪽 승리
- 매 라운드 종료 후 증강 3택 1. 증강 단계마다 새로고침 +1, 사용하지 않은 횟수는 해당 매치 동안 누적
- 3라운드 종료 후 10종 중 공통으로 제시된 이벤트 3개에 네 명이 투표. 네 명 중 한 명을 25% 확률로 추첨해 그 사람의 표 하나만 적용
- 내 전투가 먼저 끝나면 결과 화면에 머무르며, **다른 전투 보기**를 눌렀을 때만 남은 경기를 관전
- 첫 3라운드는 모든 상대를 정확히 한 번씩 만나며, 이후에는 가능한 한 직전 상대와의 재대결을 피함

## 구현 범위 (기획서 매핑)

- **캐릭터 6종**: 고양이 발바닥(되돌아가기) · 왁뿌볼(파괴 폭주) · 말랑이(말랑 방어) · 폭탄(시한폭발) · 농구공(3바운드) · 풍선(팽창 — 무기·투사체까지 커짐)
- **무기 6종**: 검 · 단검 · 활 · 권총 · 지팡이(벽 반사 마법탄) · 지뢰 — 각각 전용 스킬 + 전용 증강 3종
- **증강 105종**: 기본 스탯 / 초·후반 및 체력 조건 / 시간 성장 / 승패 누적 / 코인 계약 / 대가성 / 물리 상호작용 / 이동 방해 / 자동 공격 / 소환수 / 사망 관련 / 타격·피격 / 스킬 충전 / 빌드 연결 / 무기 전용 / **캐릭터 스킬 카피**(공용 스킬 교체)
- **현재 출전 맵**: 다이아 경기장(45도로 기울인 마름모)만 사용. 원형은 반사해도 중심에서 진행선까지의
  거리가 보존되어 중앙에 진입 불가 영역이 생기고, 두 공이 서로 다른 고리를 돌며 만나지 않는 판이
  나온다. 마름모는 그 보존량이 없어 궤도가 경기장 전체를 훑고, 법선이 축 고정이라 조준 예측선과
  실제 반사가 정확히 일치한다
- **보관 경기장 코드**: 원형 · 정사각형 · 장애물 · 파워업 큐브 경기장은 추후 재사용할 수 있도록 데이터·물리·렌더링 코드를 유지
- **타이틀 시연**: 540×960 · 30fps · 15초 무음 MP4 6종을 무작위 재생하며, `TITLE_DEMO_MODE` 한 줄로 기존 실시간 전투 시연 복구 가능
- **게임 이벤트 10종**: 다음 라운드 4인 난투(이미 탈락자가 있으면 남은 생존자 전원) · 중앙 보급 · 기둥 2개 · 매 라운드 증강 2개 · 생존자 코인 +1 · 새로고침 +10 · 다음 라운드 코인 보호/승리 보상 · 패배 시 추가 증강 · 전원 모든 피해 +30% · 변화 없음
- **모바일 메타 화면**: 3초 참가자 소개 · 코인순 4인 HUD · 장비/증강 상세 팝업 · 캐릭터 사전 장착 · 105종 도감 · 닉네임/음량/진동 설정
- **로컬 모드**: 경쟁전은 AI 랜덤 매칭과 순위별 RP 증감, 친선전은 4슬롯 로컬 방에서 AI 추가/제거 지원
- 물리: 자체 2D 반사 시뮬레이션(60fps 고정 스텝 개념), 몸통 탄성 충돌, 넉백, 중력장, 수면 기절, 빙결 등
- 공격력(무기 계열)과 모든 피해량(자동 공격·캐릭터 스킬)의 이원화 및 보호막 피해 체계 반영

## 기술 노트

- 순수 TypeScript-free JavaScript + Canvas 2D (외부 라이브러리 없음, 오프라인 동작)
- 전투 코어(`js/sim.js`)는 렌더링에서 완전히 분리 → 기획서의 "서버 권위형 시뮬레이션" 구조를
  로컬에서 그대로 재현. 추후 Colyseus 서버로 이식 시 이 코어를 서버에서 돌리고
  클라이언트는 상태를 보간해 그리기만 하면 된다 (`js/render.js`가 이미 그 역할만 담당)
- 상대 3명은 AI가 담당: 시작 방향 예측 조준, 스킬 타이밍 판단, 증강 가중치 선택
- 실제 친구 초대와 서버 권위형 경쟁전 통신은 아직 백엔드가 필요하다. 현재 친선방은 로컬+AI로 동작하며 `window.BounceRoyalRoom` 어댑터를 통해 이후 네트워크 참가자/준비 상태를 연결할 수 있다.
- 콘솔에서 `__autotest(20)` 실행 시 AI 4인 풀게임 20회 헤드리스 시뮬레이션으로 안정성 검증

## 자동 검증

Node.js가 설치된 환경에서는 아래 명령으로 전투 시뮬레이션, 대진 생성, 이벤트 데이터와 효과를 검사할 수 있다.

```bash
node tests/sim.test.js
node tests/matchmaking.test.js
node tests/events.test.js
```

## 멀티플레이 확장 로드맵 (기획서 35~58절)

1. `sim.js`의 `Battle`/`Arena`를 Node.js + Colyseus Room으로 이식 (60Hz 고정 틱)
2. 클라이언트 입력(스킬, 방향)만 WebSocket으로 전송, 판정은 전부 서버
3. 15~20Hz 상태 스냅샷 → 클라이언트 보간 렌더
4. 매치 룸 = 4인, 내부적으로 1:1 Arena 2개 또는 4인 FFA 1개 (이미 동일 구조)
